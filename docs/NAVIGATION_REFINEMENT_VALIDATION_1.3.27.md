# SolarLess Navi 1.3.27 검증 기록

## 구현 범위

1. **라벨 기반 회귀 검증:** `DriveRegression`은 현재 매칭·회전 안내 조건·이탈 정책을 같은 기록으로 다시 계산한다. 위치 정답, 회전 단계/마감 시각, 재탐색 금지 시간대 라벨을 검사한다. 라벨이 없으면 해당 지표는 null이며 통과로 해석하지 않는다. 합성 여부와 한계를 출력한다. 앱의 주행 재생 화면에도 라벨 기반 결과를 표시한다. 실제 스피커 출력 지연, 전체 Android 서비스 동작, OSRM 재탐색 완료 시간은 이 검사의 범위 밖이다.
2. **연결 도로 우회 후보:** 7일 이내 저장된 RoadPack의 법적 자동차 도로 그래프가 있을 때만 사용한다. 경로 근처 최대 96개 표본, 위험 상위 8개, 그래프 탐색 500회, 가지 길이 1.5km, 후보 최대 4개로 제한한다. 공유 OSM 노드와 회전 제한을 확인하고 다시 본 경로로 합류해야 한다. 사유지·서비스 도로·선택상 회피하는 유료 도로는 제외한다. OSRM 중간점 스냅이 30m를 넘으면 버린다. 기존 기본 2회/최대 4회 중간점 요청 예산 안에서 기존 후보보다 먼저 탐색한다. 저장 그래프가 없으면 기존 탐색을 유지한다. 회피 후보가 반드시 더 낫거나 실제 눈부심이 사라진다는 보장은 아니다.
3. **도로명 우선 표시:** 조감도 주행 화면에 현재 도로·다음 진입 도로 최대 2개를 실제 경로 위에 표시한다. 약 1초 간격과 상태 변경 시 갱신하며 500m 밖 다음 회전, GPS 불확실, 사용자 지도 탐색에서는 숨긴다. HUD/우측 조작부와의 화면 충돌을 피하고 두 이름이 겹치면 다음 도로를 우선한다. 2D/PiP에서는 기존 지도 표현을 유지한다.
4. **경로 비교 지도:** 주행 전 설정의 대안 경로 비교에서 기준 경로는 회색, 비교 경로의 다른 구간은 파랑, 대략적 공유 구간은 보라, 충분한 분석 근거가 있는 예상 눈부심 구간은 주황으로 표시한다. 동일한 반올림 좌표열만 묶는다. 경로의 실제 좌표를 그대로 그리며 공유 구간 분류만 제한된 표본으로 계산한다. 조건이 같은 분석에서만 예상 직사광선 감소를 비교한다. 닫기/Escape/Android 뒤로가기와 포커스 복귀를 지원한다. 주행 중에는 기존 텍스트 비교를 유지하고 추가 비교 지도 렌더러를 켜지 않는다.
5. **저장공간 예산:** 기본 400 MiB를 지도 32 + 정밀 자료 256 + 도로 12 + 기록/설정 여유 100으로 나눈다. 240 MiB는 정밀 자료 96, 160 MiB는 지도 20·정밀 자료 28로 줄인다. 기록/설정 여유는 실제 점유량이 아니며, 앱 전체 디스크 사용량의 강제 상한이 아니다. APK, WebView HTTP 캐시, IndexedDB 부가 용량은 제외한다. 기존 기본 캐시 상한을 늘리지 않는다. 실제 사용량을 카테고리별로 확인한다. 정밀 자료는 본문 전체를 읽지 않고 용량/사용 시각 인덱스로 집계·LRU 정리한다. 기존 자료의 용량 정보가 없거나 저장소 접근 실패 시 미확인으로 표시한다. 주행·경로 계산 중에는 삭제/예산 변경을 거부하고, 공간이 차면 새 영구 저장을 생략해 현재 사용할 자료를 보호한다. 주행 기록·즐겨찾기는 자동 삭제 대상으로 삼지 않는다.
6. **지도 프리셋:** 기본은 기존 설정, 상세는 지형·그늘을 명시적으로 활성화, 저부하는 건물·지형·그늘을 끈다. 경로선·회전 화살표·도착점·도로명 강조와 캐시는 유지한다. 개별 토글 변경 후 해당 프리셋과 다르면 개별 설정으로 표시한다. 위치·음성·회전 판단 주기는 바꾸지 않는다.

추가 유료 API, 대용량 지역 지도 DB, 자동 주행 기록 업로드는 없다. `data/scene`의 manifest/공개 ZIP/원본 추출 기준은 변경하지 않았다. 기존 자료와 캐시 형식을 읽으며 관리 정책을 개선했다.

## 개발 및 배포 검증

- Node 단위 테스트: 379개 통과. 라벨 누락/잘못된 라벨/늦은 안내 조건/금지 시간대 재탐색, 기록 해시 변경 시 배포 게이트 실패, 제한 도로 탐색과 기존 요청 상한, 지도 비교·프리셋·저장공간 보호 포함.
- 라벨 기반 배포 게이트: 합성 기록 2개 통과. 실제 폰 기록의 성능 개선 증명은 아직 없다.
- Android JVM: 36개, 실패/오류 0. `testDebugUnitTest`, `assembleDebug`, `lintDebug` 성공.
- 변경 화면 브라우저 테스트 및 전체 CI·공개 APK 검증 결과는 배포 후 아래에 기록한다.
- 의존성 감사 취약점 0. 루트/www 85개 웹 자산 SHA-256 일치. 서명키와 패키지 이름 유지, versionCode 31.

## 실제 폰에서 확인

- 기존 정식 앱에서 새 버전 확인 → 다운로드 → Android 설치 → 데이터 유지. 설치 완료 후 현재 버전 표시 확인.
- 기본/상세/저부하 프리셋 선택과 앱 재실행 시 유지, 한국어/영어 및 큰 글꼴·320px 상당 폭에서 설정 잘림 여부.
- 주행 중 삭제/예산 변경이 차단되고 안내 종료 후 가능한지, 기록 삭제 시 버튼 상태와 실제 사용량이 갱신되는지.
- 저장공간이 부족하거나 통신이 끊긴 상태에서도 새 캐시 저장 실패가 지도/안내 중단으로 이어지지 않는지.
- 같은 폰·밝기·거치·경로·날씨에서 30분 이상 비충전 주행으로 프리셋별 배터리 %p/시간·온도·렌더 지연 비교. 절감률은 현재 미측정.
- 화면 꺼짐·PiP·복귀에서 음성 누락, 이중 안내, 위치 지연이 없는지. 새 네이티브 기록 용량 표시도 실제 폰에서 확인.

## 실제 주행에서 확인

- 345 Harvard Street → 84/94 Gerry Road 같은 기존 사례를 출발 시각·날씨·선택 역할과 함께 기록한다. 주소 번호와 목적지 입구가 맞는지 먼저 확인한다.
- 저장 도로 범위 안에서 합법적 우회가 탐색되는지, 사용자가 설정한 추가 시간 예산 안에서 햇빛 차이가 실제로 있는지 확인한다. 지도상 우회가 가능해 보여도 도로 폐쇄·현장 교통·OSM 누락은 따로 확인한다.
- 병행도로·고가/지하·터널·교차로에서 잘못된 도로명, GPS 회복 직후 이름 점프, 안내 지연/불필요 재탐색을 기록한다.
- 운전 중 화면 조작/라벨 작성 대신 안전한 정차 후 또는 동승자가 기록한다. 실제 기록에는 검토한 정답 진행 거리/회전 마감/재탐색 금지 시간대 라벨을 추가한 뒤 회귀 기준에 편입한다.

## 실제 기록을 회귀 게이트에 추가하는 방법

`tests/fixtures/drive-regressions.json` 형식을 참고해 별도 로컬 manifest를 만들고 `node tools/check-drive-regressions.cjs <manifest.json> <report.json>`을 실행한다. 기록마다 SHA-256을 고정하며 위치 소스(foreground/native), 최소 라벨 수, 허용 오류 수를 명시한다. 이전 지표와 비교하려면 baseline에 같은 recordingSha256과 source 및 metrics를 넣고 maxIncrease를 지정한다. 기록/라벨/기준이 바뀌면 사람이 변경 이유를 검토해야 한다. 개인 위치 기록을 공개 저장소에 자동 추가하거나 업로드하지 않는다.

## 배포 재검증 이력

1.3.26 배포 검사(40932953577)는 기록 배치 테스트가 다른 DB의 캐시 정리 쓰기까지 세어 실패했고 공개 APK를 생성하지 않았다. 같은 소스의 메인 검사(40932948917)는 218개 브라우저 검사를 통과했다. 테스트 계측을 `solarless-drive-journal` DB로 한정하고, 동시에 지도 캐시 정리를 실행해도 기록의 한 번 배치 쓰기와 내보내기·삭제가 유지되는지 검증하도록 수정했다. 기존 태그는 보존하고 1.3.27 / code 31로 다시 전체 검사한다.

루트/www 브라우저 프로젝트는 격리된 브라우저 컨텍스트와 읽기 전용 fixture를 사용하므로 CI에서 2개 작업자로 동시에 검사한다. 검사 수나 타임아웃, 실패 판정은 줄이지 않는다. 로컬 기본값은 1개 작업자다.

1.3.27 첫 배포 검사에서는 기존 교차로 카메라 테스트가 HUD 크기 변경과 카메라 갱신 사이의 순간을 읽어 상단 경계에서 약 1픽셀 차이로 실패했다. 같은 앱 소스의 메인 전체 검사는 통과했다. 배포 태그와 앱 코드는 유지하고 전체 배포 검사를 다시 실행한다. 후속 테스트 수정은 기존 공간 경계를 완화하지 않고 HUD/카메라가 그 경계 안으로 안정되는지 최대 5초 동안 확인한다. 루트/www에서 10회 반복 검사를 통과했고 이 테스트 수정도 별도 메인 전체 검사에 포함한다.
