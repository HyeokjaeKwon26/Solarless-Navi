# 1.3.4 절전 토글 및 충전 상태 수정

## 원인

기존 상태 계산은 `manualBatterySaver || automaticBatterySaver`였고 버튼은 수동 값만 반전했다. 자동 절전 중 버튼을 눌러도 화면은 계속 절전이며, 수동 값이 true로 저장돼 충전 후에도 절전이 남을 수 있었다. 기기 상태 조회 또한 주행 중 30초 간격으로만 실행돼 안내 종료 후 충전 상태가 갱신되지 않았다.

## 동작

- 버튼은 현재 적용된 화면 모드의 반대로 전환한다.
- 수동 일반 모드 선택은 이번 JS 앱 실행 동안 자동 절전보다 우선한다. 충전 상태, Android 절전 설정, 발열 상태의 후속 조회가 수동 일반 모드를 덮어쓰지 않는다. 새 앱 실행에서는 자동 판단을 다시 허용한다.
- 수동 절전 켜기는 기존 저장값을 유지한다. 충전기를 연결해도 직접 켠 절전은 유지되고, 버튼을 눌러 해제할 수 있다. 기존 true 저장값이 실제 사용자 선택인지 과거 버그 결과인지 구분할 수 없으므로 일괄 삭제하지 않는다.
- Android 배터리·전원 연결/해제·OS 절전 설정 broadcast는 `runtimeHealthChanged`로 전달한다. 앱 시작과 복귀에서도 즉시 조회하고, 전면 화면에서는 주행 여부와 무관하게 30초 보조 조회를 수행한다.
- 진행 중인 조회에 상태 변경 이벤트가 겹치면 오래된 결과를 화면에 적용하지 않고 최신 상태를 다시 읽는다.
- 외부 전원 연결 여부를 실제 충전 중 여부와 따로 전달한다. 충전이 일시 중단돼도 외부 전원 연결 시 배터리 부족 조건은 해제한다. 발열 및 OS 절전 조건은 독립적으로 판단하되 수동 일반 모드 선택이 가능하다.
- 앱의 지도/HUD 절전 표시와 렌더링 빈도만 변경한다. Android 자체 절전 설정이나 기기의 발열 제어를 변경하지 않는다.

## 회귀 검증

브라우저 테스트는 실제 앱 HTML과 상태 처리 코드를 실행하고 Android 기기 상태 응답/이벤트를 모의 주입한다.

1. 낮은 배터리 + OS 절전 + 발열 조건에서도 한 번 눌러 일반 모드 전환.
2. 30초 후 주기 조회 및 충전 이벤트가 일반 모드를 덮어쓰지 않는지 확인.
3. 켜기/끄기를 반복하고 앱을 새로 실행하면 자동 판단이 다시 적용되는지 확인.
4. 주행 시작 전 충전기 연결/분리, 충전이 중단된 외부 전원 연결, 앱 복귀 시 상태 갱신.
5. 충전 이벤트와 이전 기기 조회가 겹칠 때 최신 상태 유지.
6. 수동 절전은 충전과 재실행 후 유지되며 버튼으로 해제 가능.

로컬 검증: Node 231개, 브라우저 root/www 70개, Android JVM 11개 통과. debug 빌드와 lint 성공(0 errors, 기존 19 warnings). root/www 50개 자산의 SHA-256 일치, npm audit 취약점 0개.

## 실기기 확인 항목

연결된 ADB 기기가 없어 실제 폰 검증은 수행하지 않았다. 아래 항목은 정차 상태에서 확인할 수 있으며 실제 주행은 필요하지 않다.

1. 기존 정식 앱 위에 업데이트해 설정·즐겨찾기·기록 유지 확인.
2. 배터리 15% 이하·전원 미연결 상태에서 앱 실행 → 자동 절전 → 버튼 한 번으로 일반 모드 전환 → 30초 이상 유지.
3. 자동 절전 상태에서 충전기를 연결해 일반 모드로 복귀. Android 절전/발열 조건이 남아 있으면 버튼으로 해제.
4. 주행 안내 시작 전과 안내 종료 후에도 충전기 연결·해제가 반영되는지 확인.
5. 화면 꺼짐/잠금 및 앱 백그라운드 동안 충전 상태를 바꾼 뒤 복귀해 상태 확인.
6. 수동 절전 켜기 → 충전기 연결 → 절전 유지 → 버튼으로 해제.
7. 일반 모드를 수동 선택한 실행에서는 자동 전환이 억제되고, 앱을 완전히 새로 실행하면 자동 판단이 다시 적용되는지 확인.
