# 1.3.33 주행 복구·기록 검증·ETA·입구·교차로 개선

## 구현한 1–5번

### 1. 화면 꺼짐 중 경로 복구

- Android 위치 서비스의 기존 수신값을 사용한다. GPS 요청 주기·정확도는 낮추지 않았다.
- 정확도 95% 환산값 25m 이내, 이동 중, 경로에서 최소 65m 이상 떨어진 위치가 8초 이상·4회 이상 이어져야 복구를 요청한다. 정차·GPS 공백·작은 평행 도로 오차로 바로 재탐색하지 않는다.
- 무료 OSRM 일반 차량 경로를 별도 스레드에서 받는다. 한 요청씩, 성공 후 30초·실패 시 60/120/240초 간격이다. 응답 2MB, 연결 8초·읽기 10초·전체 읽기 20초 한도를 둔다.
- 앱 복귀·종료·경로 변경·원래 경로 복귀 시 이전 응답을 폐기한다. 요청 후 30초 경과, 위치가 150m 이상 이동한 응답도 폐기한다. 좌표·끝점·회전 위치·도착 단계를 검증한다. 통행료 회피를 제공자가 지원하지 않으면 회피를 해제하지 않고 보류한다.
- 복구 경로는 **햇빛 분석 대기**다. 백그라운드에서는 정밀 차폐·기상·공사 피드를 다시 계산하지 않는다. 앱 복귀 시 같은 목적지의 새 후보를 기존 분석에 전달한다. 오래된 후보는 현재 위치에서 다시 계산한다.
- 목적지 부근에서 10초 이상 저속으로 머무르면 부근 도착 안내·알림을 표시한다. 완전 종료는 앱에서 확인한다. 부근을 지나 60m 이상 멀어지면 안내를 다시 허용한다.

### 2. 실제 기록의 정답 라벨·버전 비교

- 전체 설정 → 주행 재생 → `정답 라벨과 버전 비교`에서 선택한 시점의 경로 위/밖, 독립적으로 확인한 진행 거리, 회전 안내 기한, 재탐색 불필요 구간을 입력한다. 자동 매칭을 정답으로 채우지 않는다.
- 전경 GPS와 Android GPS 라벨을 구분한다. 라벨 포함 기록을 내보내 보관한다. Android는 기존 파일 저장 선택기를 사용하며 자동 업로드하지 않는다.
- 다음 버전에서도 동일한 라벨 포함 기록과 위치 출처로 평가한다. SHA-256이 다르면 비교를 거부한다. 라벨이 없는 지표는 `—`로 남는다.
- CLI: `node tools/evaluate-drive.cjs drive-labelled.json evaluation.json`.
  이전 평가 비교: `node tools/evaluate-drive.cjs drive-labelled.json evaluation.json previous.json foreground`.
- 이 재생은 매칭·안내 조건·재탐색 제안 정책 비교다. 스피커 출력, 전체 Android 실행, 실제 네트워크 지연을 재현한 시험은 아니다. 현재 릴리스 게이트 입력은 합성 기록 2개다. 현장 정확도 평가는 사용자가 라벨링한 실제 기록이 더 필요하다.

### 3. 공유 도로 구간 ETA

- 기존 `내 주행 기반 도착시간` 동의를 따른다. 동일 방향·도로 이름·전체 좌표열의 구간을 다른 경로에서도 재사용한다. 평행 도로나 반대 방향은 공유하지 않는다.
- 완전히 통과한 100m–5km 구간만 수집한다. 15초 초과 GPS 공백·불확실 매칭·2분 초과 정차 구간은 제외한다. 짧은 신호 대기는 포함하지만 정차 목적을 자동 식별하지 않는다.
- 같은 요일·2시간대·시간대 오프셋의 서로 다른 주행 5회 이상이 필요하다. 최근 2회는 검증용으로 분리한다. 기본 ETA보다 오차가 10% 이상 줄고 분산이 작을 때만 0.8–1.5배 범위로 보정한다.
- 남아 있는 공유 구간만 보정한다. 실시간 교통 반영 경로에 중복 적용하지 않는다. 최근 지연도 보정된 ETA 기준으로 계산한다.
- 전체 주행 100회, 구간 관찰 600건, 90일 한도다. 구간 좌표 대신 방향을 포함한 해시를 저장한다. `ETA 이력 삭제`는 양쪽 이력을 삭제한다.

### 4. 차량 입구 접근 순위

- 명시적 차량·주차장 입구와 공유 OSM 노드 연결을 확인한다. 접근 제한·조건부 접근·출구 전용 지점은 추천하지 않는다.
- 출발지가 저장 도로 범위 안이면 기존 그래프를 사용한다. 확인하지 못한 후보는 사용자가 입구 찾기를 눌렀을 때만 최대 3개의 차량 경로를 요청한다. 기존 요청 간격 제한을 공유한다.
- 경로 끝이 입구 12m 이내이고 도착 방향이 들어오는 연결 방향과 일치해야 `지도상 접근 확인`으로 표시한다. 확인된 접근을 먼저 두고 유턴 수·주행시간을 비교한다. 실패·요청 한도 초과 후보는 `주행 접근 미확인`으로 남긴다.
- 지도 연결은 현재 문 개방·주차 가능·사유지 허가의 보증이 아니다. 자동 목적지 변경이나 사용자 확인 체크를 하지 않는다. 응답 캐시는 2곳·10분이다.

### 5. 단계별 교차로 표시

- 먼 거리에는 출구 번호·노선·방면, 준비 단계에는 제공된 차로, 회전 직전에는 방향 화살표와 짧은 동작 문구를 표시한다.
- 화면의 준비 거리는 최소 350m, 고속에서 최대 450m다. 음성 예고/준비/실행 기준은 유지한다. 다음 회전이 180m 이내로 이어지면 보조 화살표를 표시한다.
- 차로 자료가 없으면 생성하지 않는다. GPS 불확실 시 이전 표지·차로·교차로 그림을 숨긴다. PiP 지도 전용 화면은 유지한다.

## 자동 검증

- Node 398개, 합성 주행 회귀 게이트 2개 통과.
- Android JVM 53개, debug APK, lint 오류 0·기존 경고 19 확인. 최종 CI 및 배포 검증은 아래에 추가한다.
- 전체 root 브라우저 119개 및 최종 변경에 대한 www 관련 브라우저 8개 통과: 라벨 저장/동일 증거 비교/다른 증거 거부, native 후보 인계·분석, 단계 표시, 기존 재생·차로·320px 교차로.
- GPS 구독·지도 DB·음성 엔진·모델을 추가하지 않았다. 배터리·현장 정확도·실제 음성 지연 개선은 자동 테스트만으로 확정하지 않는다.
