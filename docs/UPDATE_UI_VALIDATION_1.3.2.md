# 1.3.2 설정 진입·버튼·업데이트 검증

버전 1.3.2 / versionCode 6. 기존 정식 서명키 유지.

## 사용자 보고와 수정

사진에서 Free drive가 켜진 상태로 업데이트 확인을 눌렀을 때 기존 코드는 버전 조회 전 반환하고 작은 상태 문구만 남겼다. 확인 자체와 APK 다운로드/설치를 분리했다. 수동 확인은 안내 중에도 결과를 팝업으로 표시하고 다운로드/설치는 안내가 끝날 때까지 막는다. 네이티브 설치기의 기존 주행·서명·파일 무결성 검사는 유지한다.

기존 자동 확인은 지도 초기화 후 2.5초 타이머와 6시간 저장값에 의존했다. 이제 새 JS 앱 실행에서 지도 초기화와 독립적으로 1회 확인한다. 새 버전이 있을 때 업데이트/계속 사용을 선택한다. 계속 사용 후에는 같은 실행 중 자동 재표시나 자동 설치가 없다. 다시 실행하면 최근 확인 저장값과 무관하게 확인한다. 주행 중 자동 팝업은 주행 종료 후로 미룬다. 최신 버전일 때 자동 팝업은 띄우지 않는다.

기본 브라우저 스타일로 남아 있던 `.nav-btn`에 공통 스타일을 적용했다. 설정 버튼·업데이트 모달 액션은 최소 44px 높이, 10px 모서리, 일관된 폰트와 색상, 키보드 포커스 표시를 사용한다. 교차로 확대도 공통 토글로 변경했다. 영어/한국어 버튼을 동시에 출력하지 않는다.

320/360/384/412px 화면에서 상단 보조 버튼을 축약하고 설정 버튼을 화면 안에 확보한다. 첫 목적지 입력 화면에서 바로 설정을 열 수 있으며 Free drive나 경로 검색을 시작하지 않는다.

진단 기록 시작/정지의 비동기 핸들러는 이벤트 디스패치가 끝난 후 `event.currentTarget`이 null이 되는 문제를 수정했다. 상태 갱신은 고정된 버튼/라벨 ID로 수행하고 아이콘을 보존한다.

## 자동 검증 범위

- Node 테스트 231개.
- 브라우저 root/www: 업데이트 성공·서명 불일치·취소·손상 파일·최신 버전·네트워크 오류·네이티브 응답 지연·재시도·주행 중 수동 확인/자동 안내 지연.
- 최근 확인 시간이 저장돼 있어도 새 실행에서 확인하고, 계속 사용 시 자동 재표시와 다운로드/설치가 없는지 확인.
- 실제 앱 HTML에 네이티브 플러그인 응답을 모의 주입해 시작 팝업→계속 사용→목적지 입력→설정→수동 확인과 Android 뒤로가기 이벤트를 검증.
- 첫 화면에서 320/360/384/412px 설정 클릭, 버튼 가시성/최소 크기/공통 스타일, 주행 미시작 및 오류 없음 확인.
- 기존 경로/차로/오프라인/진단/배터리/주소 검색 테스트를 함께 수행.
- Android JVM 11개, debug 빌드/lint. 네이티브 코드는 변경하지 않았다.
- root/www 50개 파일의 SHA-256 일치, npm audit 취약점 0개.

브라우저의 네이티브 플러그인은 모의 응답이다. 실제 Android 설치기, 서비스 및 권한 흐름의 실기기 검증을 대신하지 않는다.

## 실제 폰에서 확인

1. 기존 정식 앱에 APK를 덮어 설치해 설정/즐겨찾기/기록이 유지되는지 확인.
2. 첫 화면 우측 상단 설정으로 진입. Free drive를 켜지 않은 상태에서 업데이트 확인, 도로 저장, 진단 메뉴 접근 확인.
3. Android 화면/글자 크기를 키워도 설정 버튼이 화면 밖으로 밀리지 않는지 확인.
4. 더 새 버전이 있을 때 앱을 새로 실행해 업데이트/계속 사용 선택 확인. 같은 최신 버전에서는 안내가 뜨지 않는 것이 정상.
5. Free drive 중 수동 확인은 결과를 보여주고, 안내 종료 후 다운로드·설치가 가능해지는지 확인.
6. 설치 권한 승인·취소 및 앱 복귀 동작 확인.

실제 폰 및 실제 주행으로 확인한 항목은 없다.
