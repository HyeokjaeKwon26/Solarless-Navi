# SolarLess Navi 1.3.24 — 주행 판단·복구·현장 평가

버전 1.3.24 / versionCode 28. 패키지와 기존 정식 서명을 유지한다. 유료 API·계정·서버를 추가하지 않으며 APK에 지역 지도 DB를 넣지 않는다.

## 요청한 1–8번의 구현

1. **화면/백그라운드 도로 판단:** 저장 도로의 합법적인 후속 간선 목록을 Android에 전달한다. 같은 간선 또는 허용된 연결, 진행 방향, 최근 후보 이력을 두 엔진에서 비교한다. 공유 노드가 없는 가까운 도로를 연결하지 않는다. 12,000개 간선·120,000개 연결을 상한으로 하고 그래프별로 스냅샷을 캐시한다. 네이티브의 후보 거리·채택 거리 구분도 화면과 맞췄으며, 이동 흐름 충돌 뒤 두 위치 확인 규칙을 유지한다. 같은 JSON의 직진·평행도로·연결·반대 방향·만료·GPS 공백·반복 경로 시나리오를 JS와 Java 테스트가 읽는다. 모든 실제 도로에서 동일 정확도를 보장하는 것은 아니다.
2. **이탈 재탐색:** 검증된 수신 후보 중 첫 250m에 유턴이 없는 후보를 비교한다. 선택 경로 대비 추가 2분 및 사용자 우회 한도를 모두 지킨다. 햇빛 모드에서는 동일 분석 방식·알려진 같은 기상 모드와 선택 지표가 나빠지지 않는 조건도 요구한다. 역광 회피에서는 평균뿐 아니라 강한 눈부심의 누적 시간·최장 연속 시간·부담 지표가 모두 나빠지지 않아야 한다. 후보가 없으면 기존 유효 경로를 유지한다. 추가 API 조회는 하지 않는다. 첫 재탐색 결과 확정 뒤 중복 초기 콜백이 다시 경로를 바꾸지 않도록 제한한다. 계산 중·실패·갱신 완료와 초기 유턴 회피 이유를 표시한다. 모든 도로망의 최적 경로 탐색은 아니다.
3. **눈부심 현장 평가:** 기존 사용자 관찰을 태양 고도·도로 방향·차폐·기상 자료별로 집계한다. 최소 4일·40건, 학습/검증 각각 눈부심 있음/없음 5건 이상일 때 날짜를 분리해 기준값 후보를 평가한다. 검증 자료에서 균형 오류가 기존 대비 10% 이상 개선될 때만 검토 후보를 반환한다. 자동으로 경로 색이나 음성 기준을 바꾸지 않는다. 운전자 회상은 센서 측정이 아니며 충분한 실측 자료가 없어 현장 정확도 향상을 주장하지 않는다. 기록의 태양 고도 계산은 구간/통과 시각별로 캐시한다.
4. **주소 검색 복구:** 명시적 검색 실패 또는 결과 없음 뒤 도시·주·우편번호 추가 검색, 최근 선택 주소, 지도 도착점 지정 버튼을 제공한다. 입력 도중 Nominatim 호출을 추가하지 않는다. 지도 선택도 기존 도착점 검토와 확인을 거치며 입구 확인을 자동 선택하지 않는다. 출발지 검색에서는 목적지 핀 버튼을 제공하지 않는다. 도로 데이터에 없는 번지를 만들어내지 않는다.
5. **복잡한 교차로:** 가까운 복잡한 회전에서 실제 선택 경로의 앞뒤 모양을 작은 SVG 개요로 표시한다. 기존 출구 번호·다음 회전·차로 정보는 유지한다. 현재 차로 감지가 아니며 없는 연결이나 차로를 그리지 않는다. GPS 불확실·PiP에서는 표시하지 않고 낮은 가로 화면에서는 숨긴다. 좁은 세로 화면에서 교차로/하단 요약 사이 공간이 부족하면 도구를 자동으로 더보기로 접고 재중앙을 유지한다. 펼친 도구는 남은 공간 안에서 스크롤하며 닫기·재중앙을 고정한다.
6. **ETA의 근거:** 같은 경로/시간대의 유효 기록 5건 이상이면 과거 소요시간 비율의 10–90 백분위 범위를 표시한다. 예측 신뢰구간이나 실시간 교통 범위가 아니다. 최근 60초에 경로 진행이 기본 예상보다 느린 부분은 최대 60초의 지역 지연으로만 반영한다. 전체 남은 도로에 배율로 확장하지 않는다. 개인 보정 또는 실시간 교통이 적용되면 이 지연을 중복 가산하지 않는다. 오래된 GPS·재탐색·역행·예상치 급변에는 초기화하고, 진행이 회복되면 창에서 사라진다.
7. **서비스·백그라운드 복구:** 경로 서버와 검색 공급자별 장애 상태를 분리한다. 두 차례 네트워크/5xx 오류 뒤 2초부터 최대 60초, 429는 Retry-After를 반영해 30초–5분 동안 요청을 보류한다. 취소는 장애로 세지 않으며 성공하면 해제한다. 기존 OSRM 1초 요청 간격은 유지한다. 네이티브 경로 전달 오류에도 별도 재시도 간격을 적용한다. GPS 수신/회전 판단에는 대기 시간을 넣지 않는다. 기존 복원·PiP·백그라운드 안내와 확인 후 주행 재개 흐름을 유지하며, 종료 시 새 상태 표시를 정리한다. 공용 서버 가용성을 보장하지 않는다.
8. **배터리·발열 측정과 비교:** 사용자가 켠 주행 진단에서 기존 기기 상태 조회에 맞춰 최대 30초마다 버전·기기·충전·밝기·온도·화면 모드·렌더 지연 표본을 기록한다. 별도 GPS나 빠른 폴링을 추가하지 않는다. 주행 재생 화면에서 이전 JSON과 비교할 수 있다. 30분 이상, 비충전, 고정 밝기, 동일 기기/화면 모드, 연속 표본을 확인할 수 있을 때만 배터리 소모(%p/시간)를 비교한다. 경로·날씨·거치 조건은 사용자가 맞춰야 한다. 렌더 값은 주기적으로 채집한 최근 render 이벤트 지연이며 실제 패널 FPS나 모든 프레임의 p90이 아니다. 실제 절감률은 미측정이다.

Android 주 GPS 250ms/1m, 네트워크 위치 요청, 기존 음성 단계와 회전 판단 주기는 유지한다. 광역 실시간 교통·자동 차로 인식·전국 오프라인 DB는 추가하지 않는다.

1.3.24 이전의 기록에는 비교에 필요한 충전·밝기·화면 모드 정보가 없을 수 있다. 이 경우 비교를 거부하며, 누락값을 추정해 이전 버전 대비 절감률을 만들지 않는다. 이번 버전에서 조건을 맞춘 기록을 이후 버전의 비교 기준으로 사용할 수 있다.

## 자동 검증

- Node 단위 테스트와 Java/JS 공유 GPS 시나리오, Android JVM·빌드·lint를 수행한다.
- root/www에서 검색 복구 입력·핀 확인, 320px 교차로/도구 배치, GPS 불확실 시 확대도 숨김, 관찰 자료 부족 표시, 충전 기록의 성능 비교 거부, ETA 근거 표시, 네이티브 전송 오류 후 제한된 재시도를 검사한다.
- 기존 음성·경로·미리보기·단위·업데이트·오프라인 자료·주행 설정 회귀 검사를 함께 실행한다.
- 공개 후 실제 APK 서명·크기·해시·버전·웹 파일 일치 및 업데이트 응답을 별도로 확인한다. 최종 결과는 공개 검증 기록에 추가한다.

### 로컬 실행 결과

- Node 357개 통과. 같은 JSON의 8개 GPS 시나리오를 JS와 Java에서 실행했다.
- Android JVM 36개 통과, debug 빌드·lint 성공.
- 신규 기능·간결 도구 root/www 화면 12개 통과. 기존 주행 기록 재생 및 개인 ETA 표시 4개도 통과했다.
- 첫 화면 검사에서 GPS 불확실 시 확대도 숨김과 320px 도구 겹침을 보강했다. 네이티브 후보 거리 기준을 맞추는 과정에서 이동 충돌 뒤 복구 상태를 유지하도록 수정하고 기존 회귀 검사를 재통과했다.
- 전체 CI에서 자동 접기 이전의 3D 버튼 노출 조건을 발견해 더보기 접근성 검사로 갱신했다. 이어 버튼 포커스와 화면 회전 시 지도 컨테이너가 스크롤되는 문제를 재현해 스크롤을 막고, 지도 위치·버튼 조작·가로 배치를 함께 검사한다. 테스트 종료 중 초기화 대화상자의 닫힌 페이지 오류도 테스트 정리 단계에서만 처리한다.
- 웹 자산 77개 root/www SHA-256 일치, 버전 단조 증가 확인, npm audit 취약점 0개. 전체 브라우저 검사는 배포 CI에서 실행한다.
