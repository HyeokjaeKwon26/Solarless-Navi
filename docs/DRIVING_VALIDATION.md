# 주행 품질 개선 및 실기기 검증

작성일: 2026-10-23. 자동 테스트는 합성 위치·서비스 응답을 사용한다. 실제 주행 성능이나 햇빛 감소율을 측정한 결과가 아니다.

## 자동 검증 결과

- Node 24 단위 테스트 192개 통과. 기록 재생 CLI, GPS 정확도/오래된 위치/연속 이탈, 도착 조건, 차로 정보, 경유점 예산, 도로 방향과 표지판 필터를 포함한다.
- Chromium 브라우저 테스트 14개 통과(root와 www 각각 7개). 지도 로드/폴백, 자유 주행과 화면 복귀, 목적지 변경 응답 경쟁, 진단 저장, 오프라인 이탈/연결 복구, 차로 표시와 GPS 중단/복구를 포함한다.
- JavaScript 구문 검사 및 root/www 41개 자산 SHA-256 일치 확인. `npm audit` 취약점 0개.
- Capacitor Android 자산 반영 및 `assembleDebug` 통과. 디버그 APK 생성 완료. Android 저장창과 실제 GPS·PiP·음성은 컴파일로 동작을 확정하지 않았다.
- 합성 기록 예제: 8개 샘플 중 6개 허용, 낮은 정확도 1개·오래된 위치 1개 거절, 연결 복구 후 재탐색 판단 1회. 실제 도로의 오재탐색률 측정 결과가 아니다.

## 이번 변경

1. GPS 기록·재생: 설정 패널에서 기록을 시작/중지하고 JSON을 저장한다. 위치·시간·정확도·속도·경로까지 거리·연결 상태를 기록한다. 기본은 꺼짐이며 메모리에서만 유지하고 자동 업로드하지 않는다. 최대 14,400개 샘플 이후에는 추가 샘플을 버리고 `dropped`에 집계한다. 앱 종료 전 저장해야 한다. Android는 시스템 저장창, 브라우저는 파일 다운로드를 사용한다.
2. 주행 판단: 정확도 반경을 뺀 경로 이격이 45m를 넘는 상태가 최소 3회·2초 지속될 때 재탐색한다. 요청 간격은 최소 8초이며 중복 요청을 막는다. 이 수치는 실주행 검증 전의 보수적 초기 설정이다. GPS가 10초 이상 오래되었거나 미래 시각이면 안내에 반영하지 않는다. 도착은 목적지 거리 35m 이하, 경로 잔여거리 65m 이하, GPS 정확도 25m 이하, 속도 20km/h 미만을 함께 요구한다.
3. 장애 복구: 연결 단절 중 기존 경로를 유지한다. 경로 이탈이 확인되면 이전 경로의 회전 안내를 멈춘다. 연결 복구 후에도 이탈 상태와 신선한 GPS가 확인된 경우에만 현재 위치에서 재탐색한다. GPS/연결/경로 서버 상태를 지속 표시한다. 오프라인 새 경로 계산을 지원하는 것은 아니다.
4. 햇빛 경로: 실제 도로 경로 중간 지점의 양쪽에서 후보를 탐색한다. 그늘/눈부심 모드는 기본 대안이 3개여도 최대 2개 경유점 요청을 허용한다. 명시적 요청 예산 0을 존중한다. 기존 우회시간 제한과 동일 분석 수준끼리의 비교는 유지한다. 카드에는 후보 내 우회시간과 햇빛 노출시간 감소 추정치를 함께 표시한다. 전체 도로망의 최적 그늘길을 보장하지 않는다.
5. 안내 정보: OSRM이 해당 회전 지점에 명시적으로 제공한 유효 차로를 500m 이내에서 표시한다. 데이터가 없으면 표시하지 않는다. 목적지를 주변 도로로 조정한 경우 출입구 미확인임을 표시한다. 양방향 도로의 방향을 올바르게 비교하고, 표지판이 현재 도로에 속하며 앞에 있을 때만 STOP/톨게이트 후보로 표시한다. 자료가 부족하면 생략한다. 전용 단속카메라 데이터는 추가하지 않았다.
6. 검색: 자동완성의 Nominatim 호출을 제거하고 명시적 검색 제출에만 사용한다. 공개 API의 앱 전체 트래픽 제한을 해결하는 운영 구조는 별도 과제다.

## 기록 재생

Node 24에서 프로젝트 루트를 기준으로 실행한다.

```sh
npm run replay:drive -- tests/fixtures/drive-synthetic.json
npm run replay:drive -- /path/to/solarless-drive.json /path/to/report.json
```

재생은 네트워크를 사용하지 않으며 앱의 GPS 유효성·경로 이탈 판정 함수를 실행한다. 수신/거절 사유, 허용된 위치 사이의 최대 시간 간격, 재탐색 판단 횟수를 출력한다. 실제 앱의 센서 공급자 우선순위·중복 샘플 제거·지도 매칭·음성·카메라·API 응답 순서 전체를 재현하는 도구는 아니다. 재탐색 횟수는 해당 기록 조건에서 판정 함수가 요청을 허용한 횟수다.

실제 경로 이탈 여부를 사람이 확인한 샘플에 `expectedOffRoute: true/false`를 추가할 수 있다. 라벨이 없으면 오재탐색 비율은 `null`이며 0%로 보고하지 않는다. 합성 예제의 0%를 실제 성능으로 해석하지 않는다. 기록 파일에는 위치와 시간이 있으므로 공개 저장소에 올리지 않는다. 저장창에서 선택한 외부 저장 위치의 동기화는 해당 서비스 설정을 따른다.

## 실제 주행이 필요한 항목 — 모두 미실시

조작과 기록 메모는 동승자가 담당하거나 정차 후 수행한다. 각 항목에 기기/Android 버전, 앱 커밋, 날짜, 경로, 재현 조건, 결과를 기록한다.

| 순서 | 시나리오 | 확인할 내용 | 남길 자료 |
|---|---|---|---|
| 1 | 정차 상태와 도심 15분 | GPS 튐으로 재탐색·도착이 발생하지 않는지, 신호 저하 표시 | 진단 JSON, 실제 이탈 여부 메모 |
| 2 | 평행도로·고가/하부도로·램프 | 다른 도로로 붙지 않는지, 실제 이탈 후 재탐색까지 시간 | 위치 기록, 동승자 관찰 시각 |
| 3 | 터널 진입·통과·출구 | 오래된 위치로 새 안내를 하지 않는지, 출구에서 정상 복구 | 신호 중단/회복 시각, 안내 내용 |
| 4 | 통신 단절 상태에서 경로 유지/이탈 후 복구 | 기존 경로 유지, 이탈 후 회전 안내 중지, 복구 시 현재 위치 출발, 중복 요청 여부 | JSON, 연결 상태 변경 시각 |
| 5 | 복잡한 교차로와 연속 회전 | 음성 시작 시점, 차로 표시와 실제 도로의 일치, 이전 회전 안내 재등장 여부 | 회전 지점별 관찰 기록 |
| 6 | 목적지 앞 도로를 지나감·주차장 진입 | 지나가는 동안 도착하지 않는지, 실제 도착 후 정상 종료, 출입구 표시의 정확성 | 실제 출입구와 안내 종점 비교 |
| 7 | 전화 수신·다른 앱·화면 잠금·PiP | 위치 서비스와 음성 복귀, 이중 안내, 화면 방향·차로 표시 | 기기별 단계와 재현 결과 |
| 8 | 충전/미충전 각 60분 이상 | 발열, 배터리 소비, 프레임 저하, 메모리/앱 종료 | 시작/끝 배터리, 온도, 사용시간 |
| 9 | 진단 파일 저장·취소·앱 복귀 | Android 저장창 실제 저장/취소와 재생 가능 여부, 저장 후 안내 지속 | 내보낸 JSON 및 재생 보고서 |
| 10 | 출퇴근 정체/비정체 | 출발 시 ETA와 실제 도착시간 차이 | 출발 ETA, 실제 시간, 거리, 교통 상황 |

GPS가 잠깐 끊겼을 때 센서로 위치를 추정하는 기능과 차량 화면 연동은 이번 범위에서 구현하지 않았다. 같은 시간·같은 구간의 상용 내비 비교가 필요하며, 플랫폼별로 별도 기록한다.

## 햇빛 회피 실증 — 미실시

- 빠른 경로와 그늘 경로를 같은 출발 시각대·비슷한 날씨에서 반복 비교한다. 순서를 바꾸어 날짜/구름 차이가 한 경로에만 유리하지 않게 한다.
- 예측한 노출시간, 실제 햇빛/그늘 관찰시간, 추가 주행시간, 건물·지형 데이터 확보 여부를 함께 기록한다. 가로수, 구름, 건물 높이 누락 구간을 따로 표시한다.
- 눈부심은 운전자 방향과 실제 체감 시점을 별도로 기록한다. 도로 노출시간을 차내 온도·피부 노출·건강 효과로 변환하지 않는다.
- 대표 지역에서 효과가 반복되는지 확인하기 전에는 상용 내비보다 낫거나 노출을 특정 비율 줄인다고 홍보하지 않는다.

## 별도 서비스/데이터가 필요한 과제

실시간 교통 반영, 실제 출입구 데이터, 지속 갱신되는 안전운전/단속 정보, 오프라인 지도·라우팅, Android Auto/CarPlay는 별도 개발과 제공 범위 검토가 필요하다. 자체 지도 서버 없이 관리형 제공자를 사용할 수 있다. 차로 정보는 [OSRM 응답 규격](https://project-osrm.org/docs/v5.24.0/api/#intersection-object)을 따르며 지역별 누락이 가능하다. 공개 검색의 제한은 [Nominatim 이용 정책](https://operations.osmfoundation.org/policies/nominatim/)을 따른다.
