# SolarLess Navi 1.3.20 검증 기록

작업일: 2026-10-29 (America/New_York). 버전 1.3.20, Android versionCode 24.

## 구현 범위

### 1. 실제 기록 재생·비교

- 설정 → 주행 진단 → **주행 재생·눈부심 평가**에서 저장된 기록을 불러오거나 JSON 파일을 선택한다. 지도에 원시 GPS, 다시 계산한 경로 매칭 위치, 당시 경로를 구분하고 슬라이더 또는 재생으로 이동한다.
- 앱 화면 GPS와 Android 서비스 GPS를 선택한다. 두 스트림을 합쳐 중복 위치를 만들지 않는다. 백그라운드 정확도는 Android의 68% 반경을 기존 정책과 같은 배율로 변환한다.
- 기존 기록의 매칭 성공 여부를 정답으로 사용하지 않는다. 현재 GPS 검증·경로 매칭 규칙으로 다시 계산한다. 경로 없는 구간과 거부된 위치도 집계한다.
- 명시적 정답 위치 `expectedProgressMeters`/`expectedToleranceMeters`, 회전 안내 기준 이벤트 `turn-ground-truth`(`utteranceId`, `latestRequestAt`)가 있을 때만 오류율을 계산한다. 라벨이 없으면 `null`이다. 음성 요청 시각은 실제 스피커 재생 시각이 아니다.
- CLI: `node tools/replay-drive.cjs drive.json before.json`, 업데이트 후 `node tools/replay-drive.cjs drive.json after.json before.json`. 원본 파일 SHA-256이 같아야 비교한다. GPS 거부·불확실·진행 급변, 라벨이 있는 오매칭/안내 지연, 기존 재탐색 및 ETA 지표를 확인할 수 있다.
- 화면 입력은 최대 16 MiB, 재생은 최대 50,000개 샘플/60,000개 이벤트 및 2,500만 기하 비교로 제한한다. 주변 도로 전체 그래프와 실제 음성·지도 영상은 기록에 포함되지 않으므로 재생은 GPS/선택 경로 알고리즘 평가이며 전체 실행 환경 복제는 아니다.

### 2. 주변 도로 후보 검증

- 기존 선택 저장 도로의 방향별 간선을 후보로 조회한다. 위치·주행 방향과 직전 후보의 동일 간선 또는 합법적인 노드 연결을 비교한다. 저장 영역 교체 시 이전 후보 이력을 재사용하지 않는다.
- 평행도로가 충분히 구분되지 않거나 선택 경로보다 가까운 다른 도로가 있으면 원시 위치를 유지하고 확정 안내를 보류한다. 기존 두 번의 확실한 위치 관측 후 복구 규칙을 유지한다.
- Android 서비스에는 최대 12,000개 간선의 유효기간 있는 스냅샷을 전달한다. 네이티브 검사는 방향·거리·평행도로 모호성을 보수적으로 확인한다. JS의 연결 이력 점수와 동일한 전체 매칭 엔진은 아니다.
- 저장 도로가 없거나 만료되면 기존 선택 경로 매칭을 사용한다. 12,000개 간선을 초과한 저장 영역은 네이티브 주변 도로 보조 검사를 생략한다. 추가 자동 도로 다운로드나 GPS 업로드를 하지 않는다.

### 3. 조감도 카메라·성능

- 굽은 구간은 더 넓게 보고 기울기를 낮춘다. 가까운 교차로는 기존 32° 및 HUD 영역을 고려한 회전 지점 맞춤을 우선한다. 정차 중 방향을 유지하고 움직일 때 최단 각도로 부드럽게 복원한다.
- 표시 중인 화면의 animation-frame 빈도를 관찰한다. 지속적인 24 fps 미만 상태 또는 Android thermalStatus 2 이상이면 픽셀 비율 상한을 1.5에서 1로, 차량/카메라 갱신 상한을 약 30 Hz에서 15 Hz로 낮춘다. 이는 GPU 렌더링 fps의 직접 측정은 아니다.
- 발열이 낮고 관찰 빈도가 40 fps 이상인 안정 상태를 15초 유지한 뒤 복원한다. 정차/수동 지도 탐색에서 희소한 렌더링을 낮은 fps로 오인하지 않는다. 기존 절전·PiP·위성·WebGL 실패 시 2D 전환은 유지한다.

### 4. 눈부심 관찰

- 주행 기록을 켠 경우 화면 GPS의 매칭 주석에 당시 예측 위험도, 계산 시각, 도로 방향, 예상 통과 시각, DNI, 기상 모델, 차폐 정도·시각을 함께 남긴다.
- 안내 종료 후 선택한 기록 지점에 눈부셨음/아니었음을 저장한다. 관찰은 기억에 의한 자기보고이며 센서 측정이 아니다. 같은 시각·위치는 수정 가능하다.
- 기상·차폐 증거가 없는 예측은 미확인으로 분리한다. 음성 안내/경로 색상에 관찰 결과를 자동 반영하지 않는다.
- 위치·시각을 포함한 관찰은 로컬 최대 200건·90일 보관한다. 기록 내보내기에 포함하고 평가 삭제 또는 저장 기록 삭제로 제거한다. 백그라운드 전용 GPS에는 화면의 눈부심 예측이 없을 수 있다.

### 5. 차량 입구 후보

- 목적지 확인 화면에서 사용자가 누를 때 반경 350m의 OSM 도로·차량 입구 자료를 조회한다. 충분한 저장 도로가 있으면 우선 사용한다. 요청 간격 1분, 10분 캐시, 응답 1.5 MB 제한이다.
- Android에서는 Capacitor의 네이티브 HTTP에 앱 식별 User-Agent, 연결 5초·읽기 15초 제한을 직접 전달하고 화면 대기는 최대 20초로 제한한다. 일반 브라우저는 fetch 15초 제한을 사용한다. Capacitor 6의 patched POST fetch가 AbortSignal을 전달하지 않는 문제를 피한다.
- 차량/주차장 입구 태그가 있고 합법적인 진입 방향의 공유 OSM 노드로 연결된 후보만 최대 5개 표시한다. 사유지·조건부 접근·출구 전용·단순히 가까운 비연결 입구는 추천하지 않는다.
- 선택하면 도착 핀을 옮기지만 ‘직접 확인한 입구’ 체크를 자동 선택하지 않는다. 이후 일반 경로 계산으로 접근을 확인한다. 현장 표지·개방 시간·주차 공간은 검증하지 않는다.

### 6. 구간 자료 상태·복구

- 안내 종료 후 설정의 **정밀 자료 상태·복구**에서 현재 지도 중심 타일을 조회한다. 출처, OSM 추출 시각, 릴리스 이름, manifest 확인 시각, 캐시 상태와 타일의 건물/터널/지형/건물 지면 포함 여부를 구분한다.
- 원본 추출 30일 경과와 최신 manifest 미확인은 별개로 표시한다. 릴리스 날짜를 OSM 원본 날짜로 표시하지 않는다. 상태 조회만으로 ZIP을 다운로드하지 않는다.
- 복구는 해당 타일이 든 ZIP 하나만 다운로드하고 기존 해시 검증을 거쳐 요청 타일만 추출한다. 전체 캐시를 지우지 않으며 다운로드·해시·JSON 실패 시 기존 정상 캐시를 보존한다. 다음 경로 분석부터 반영한다.
- 기존 schema 2/3, 한국·미국 권역 manifest 및 과거 릴리스 자산을 유지한다. 이번 기능 작업에서 OSM 원본을 새로 추출하거나 기존 지도 자산을 변경하지 않았다. 이전 호환성 확인은 `SCENE_DATA_STATUS.md` 및 연결 기록 참조.

## 자동·개발 환경 검증

- Node 331개 검증 범위: 신규 주변 도로/입구/재생/발열 정책/관찰/선택 복구 및 기존 회귀. CLI 비교와 Android HTTP 시간제한도 확인한다.
- 최종 변경 대상 root/www 브라우저 10개 통과: JSON 불러오기·평가 보관·GPS 출처 선택, 320px 배치, 단일 구간 복구, 입구 선택·미확인 상태, 단위 저장, 실제 MapLibre의 발열 해상도 제한.
- Android JVM 31개 통과, debug APK 빌드 성공, lint 0 errors / 기존 19 warnings. API 22~23에서 지원하지 않는 정렬 호출을 호환 호출로 수정했다.
- 고정된 릴리스 소스의 전체 브라우저 및 배포 검증은 아래 최종 결과에 기록한다.
- 의존성 audit: 취약점 0. root/www 68개 자산 SHA-256 일치.
- 실제 공개 manifest 조회에서 Boston 타일 `160:96`의 출처·원본 날짜·ZIP 크기를 확인했다. 입구 검색 공개 서버는 이번 실행 환경에서 429 또는 시간초과를 반환했다. 따라서 온라인 실자료 입구 검색의 성공은 확인하지 못했으며, 후보 필터링·선택 화면·Android HTTP 인자는 모의 응답으로 검증했다. 서비스 사용 불가 시 저장 자료 또는 수동 도착 핀을 사용한다.

## 실제 폰에서 확인할 항목 — 개발 환경 테스트로 대체하지 않음

1. 기존 정식 앱에서 1.3.20 업데이트 알림 → 다운로드 → Android 설치 승인 → 설정·즐겨찾기 유지. 이후 버전 업데이트도 같은 경로로 확인.
2. 실제 저장 도로를 준비하고 GPS가 흔들리는 평행도로·고가/하부도로에서 화면과 음성의 보류/복구 확인. 화면 끄기·PiP에서도 잘못된 회전 안내를 하지 않는지 확인. 정답 도로와 시각을 별도 기록.
3. 평행도로에서 정상 도로까지 과도하게 불확실 상태로 남지 않는지, 실제 이탈 후 재탐색이 지나치게 늦지 않는지 확인.
4. 곡선·정차·고속·연속 회전·가로 거치에서 지도가 튀지 않는지 확인. 20~30분 사용으로 발열·배터리·해상도 저하 및 안정 후 복구를 확인. 실제 fps/소모량 개선은 아직 측정하지 않음.
5. 주행 기록을 켜고 화면을 끄거나 PiP로 전환한 뒤 종료한다. Android GPS 스트림 재생, 기록 누락·시각·위치 정렬, 파일 선택과 내보내기를 확인.
6. 눈부셨던 구간/아닌 구간을 안전하게 정차한 후 평가한다. 유리 반사·차량·나무·구름 등 모델 밖 요인을 별도 메모해 예측과 자기보고 차이를 검토.
7. 실제 목적지 차량 입구와 추천 핀, 일방통행 진입 방향, 사유지·출구 전용 제외, 검색 실패 시 직접 핀 조정 확인. 무료 OSM에 입구가 없으면 목록이 비는 것이 정상.
8. 모바일망에서 현재 구간 상태 → 해당 자료 복구 → 다음 경로 계산 반영 확인. 통신 중단/저장소 부족/손상 ZIP에서도 기존 정상 자료가 유지되는지 확인.

주행 중 재생·평가·자료 복구 화면을 조작하지 않도록 안내 종료 후에만 열 수 있게 했다. 이 목록의 실제 폰/주행 검증은 아직 수행하지 않았다.
