# 1.3.37 주행 연속성·검색·도착 개선

## 요청 1–6번의 구현 범위

1. **주행 오류 검토:** 라벨과 재생 결과가 다른 위치, 안내 조건이 늦은 시점, 재탐색 불필요 구간에서 발생한 재탐색 제안을 최대 200개 목록으로 표시한다. 선택하면 해당 프레임으로 이동한다. 자동 매칭을 정답으로 채우지 않으며 합성 기록과 가져온 기록을 구분한다. 사용자는 현재 실제 주행 JSON이 없다고 답했다. 따라서 실제 주행 오류 감소·정확도 검증은 미완료다. 기존 합성 회귀와 추가 오류 검토 검사는 현장 자료를 대체하지 않는다.

2. **백그라운드 경로 선호:** 기존 GPS·복구 간격을 유지하고 한 OSRM 응답의 검증된 후보 최대 3개를 비교한다. 편한 경로는 회전·분기·유턴과 우회 시간으로 비교하며 추가 2분, 20%, 사용자 한도를 넘지 않는다. 햇빛 비교는 전경에서 이미 계산한 기상·차폐 자료 최대 512개만 전달한다. 10분 이내 스냅샷, 예상 통과 시각 차이 2분 이내, 같은 방향·선분 2m 이내 자료가 모든 평가 표본에 있어야 한다. 경로별 최대 1,024개 표본, 최소 10% 지표 개선, 강한 위험 시간·최고 위험 비악화를 요구한다. 그늘 선호는 저장된 차폐 비율로 계산한 노출 시간을 비교한다. 새 기상·차폐 분석이나 차량별 눈부심 실측이 아니다. 자료가 없거나 우회 이득을 확인하지 못하면 일반 차량 경로로 복구한 이유를 알림에 표시한다. 앱 복귀 후 기존 정밀 분석을 갱신한다. 정체·폐쇄의 최신성이나 모든 경로 탐색을 보장하지 않는다.

3. **여행별 통신 끊김 대비:** 설정의 경로 선택 아래 `이 경로의 통신 끊김 대비`에서 선택 경로·회전 정보를 명시적으로 저장한다. 한 여행·1MiB·24시간 제한이며, 같은 출발점 15m 이내·같은 목적지 5m 이내·방향·통행료 조건이 맞을 때만 통신 실패 후 재사용한다. 새 출발점에 저장 경로를 직선으로 붙이지 않는다. 주변 도로 저장은 12km 이하 경로, 500m 간격의 약 700m 폭 상자로 한 번 요청한다. 원본 도로·공유 노드·회전 제한을 함께 저장하며 기존 12MiB 도로 예산에 여행 자료도 포함한다. 도로는 7일 유효하며 새 저장은 이전 지역을 대체한다. 배경 지도·전국 DB를 다운로드하지 않는다. 100m 간격의 도로 표본 포함 여부와 빠진 위치를 표시하지만 완전한 연결·우회 가능·전체 배경 지도 준비를 의미하지 않는다. 화면 꺼짐 중 새 오프라인 경로를 계산하는 기능을 추가한 것은 아니다.

4. **갈림길 표시:** 기존 교차로 개요에 저장 도로의 연결을 회색으로 표시하고 선택 경로를 파란색으로 강조한다. 정확한 공유 OSM 노드와 진입 방향을 확인하고, 적용 가능한 회전 제한을 지킨 연결만 최대 8개 표시한다. 좌표상 교차하지만 노드가 다른 고가·지하 도로를 연결하지 않는다. 명시적인 진입 도로의 교량·터널 태그가 있으면 문구로 표시한다. 태그 없는 높이나 차로는 만들지 않으며 전체 입체 교차로 모형은 아니다. 자료가 없으면 기존 선택 경로 그림을 유지한다.

5. **주소 결과 근거:** 기존 번지 엄격 필터를 유지한다. 결과 아래 번지·도로명 일치, 도로만 일치, 번지 차이, 명시한 지역 미확인, 장소 결과를 구분한다. 기본 도로 약어를 정규화한다. 쉼표 없는 복잡한 주소나 지원하지 않는 약어는 보수적으로 미확인으로 표시할 수 있다. 번지 일치는 실제 입구 확인과 다르다. 기존 전체 주소·최근 검색·사용자가 확인한 입구 재사용 흐름을 유지한다. 추가 검색 공급자나 자동 요청은 없다.

6. **주차 후 목적지 확인:** 도착 창에서 사용자가 안전하게 정차했음을 체크한 뒤 새 위치를 받아 저장한다. 15초 이내·정확도 25m 이내 위치가 필요하며 알려진 속도가 3.5km/h를 넘으면 거부한다. 속도 미제공 시 사용자의 정차 확인을 따른다. 주차점·당시 선택 목적지·이름·시각을 로컬에 1건·30일 보관하고 삭제할 수 있다. 두 점 사이의 직선거리와 방위를 표시하며 보행 경로나 통행 가능으로 표현하지 않는다. 자동 주차 추정·위치 업로드·백그라운드 위치 추적은 추가하지 않았다.

GPS 수신·매칭·음성 시점을 늦추지 않는다. 기존 지도 ZIP·manifest는 변경하지 않았다. 새로운 유료 서비스·음성 엔진·대형 지도 모델은 없다. 추가 표시·캐시의 실제 전력 영향은 미측정이다.

## 검증

- Node 405개, 기존 합성 주행 회귀 2개 통과. 신규 검사는 잘못된 출발점·목적지·방향·통행료·만료, 주차 확인·신선도·정확도·이동, 번지·도시 분류, 캐시 상한, 공유 노드 없는 교차 도로, 라벨 오류 시점 분류를 포함한다.
- Android JVM 57개 통과. 추가 후보의 시간/유턴 한도, 시간 만료·반대 방향·평행 도로·부분 자료 거부 및 비교 가능한 햇빛 후보 선택을 검사한다. APK 빌드·lint 통과(오류 0, 기존 경고 19개).
- 최종 1.3.36 로컬 전체 브라우저 124개 통과. 구현 후보 단계에서 변경 관련 www 브라우저 8개도 통과했다. 준비 경로의 저장·재시작, 좁은 화면의 주차 확인·저장·삭제, 주소 근거 표시를 포함한다.
- 화면 검사에서 경로 계산 중 저장이 먼저 활성화되던 상태를 수정했다. 주차 저장 검사는 경로 계산 완료 상태에서 사용자 정차 확인 후 수행한다.
- 1.3.35 후보의 CI에서 폐쇄 제안 검증이 실패해 APK는 공개되지 않았다. 후보 분석 전 GPS만 주입하던 준비 과정에 계산 완료·최신 위치 확인을 추가했고, 오래된 위치·계산 중 상태에서는 제안을 거부하는 회귀 검사를 추가했다. 기존 관련 검사 3개를 두 웹 묶음에서 각각 3회, 총 18회 반복 통과했고 새 거부 조건 검사는 총 4회 통과했다. 앱의 GPS 신선도·계산 중 제안 제한은 완화하지 않았다.
- 1.3.36도 배포 CI의 준비 과정에서 2개 실패해 공개되지 않았다. 재시작 후 경로에도 같은 준비 함수를 사용하고, 계산 완료 대기를 기본 5초에서 최대 15초로 명시했다. 폐쇄 관련 검사 자체의 총 제한은 60초이며 앱의 계산·GPS 기준을 바꾼 것은 아니다.
- 최종 준비 함수로 관련 4개 검사를 root/www에서 각각 3회 반복해 총 24개 통과했다. Chromium CPU를 4배 느리게 제한한 별도 검사에서도 두 묶음 8개 모두 통과했다. 이는 실기기 전력·성능 측정이 아니라 테스트 타이밍 검증이다.
- 최종 1.3.37 CI에서 Node 405개, Android 빌드·단위 검사·lint, root/www 브라우저 각 124개(총 248개), 합성 주행 회귀 2개, 웹 파일 96개 일치를 통과했다. [main CI](https://github.com/HyeokjaeKwon26/Solarless-Navi/actions/runs/41111577762)와 [배포 CI](https://github.com/HyeokjaeKwon26/Solarless-Navi/actions/runs/41111581515)에서 확인할 수 있다.
